## 1. 触发时机总表

| 信号 | 动作 |
|---|---|
| 学生主动："复盘/打卡/本周结束了/我偏了/跟不上了" | 按语义进入打卡或复盘 |
| 打卡消息（任意时间） | 日打卡流程（§2） |
| 周计划全部任务达终态且新周未结算 | 自动结算触发（settle） |
| 里程碑到期日 | 里程碑验收（见 voyage.md §9） |
| 每月结束后学生首次出现 | 月度总结补做提示（§11） |
| 学生周中再现且当周数据明显偏弱 | 先问一句"这周有点静，一切都顺利吗？"再进正常流程 |

## 2. 日打卡（轻）

**流程**：学生一句话打卡 → 调 `compass_store.py checkin`（脚本内部：匹配当日计划项 → 提取量 → 标记 → 追加 daily 日志 → 更新 streak → 输出口播摘要含近期摘要）→ LLM 凭脚本输出转述 + 生成鼓励语。**LLM 零额外数据读取。**

- **无压力剩余提醒**：打卡回复附加一行「✅ 已记下！今天还有 2 项待完成：B、C」；当日全部完成时改发"今日清盘"结算语（见 templates.md 语料库）。
- 未匹配到计划项 → 登记"计划外完成"，供周复盘分析（"今天多做了个英语精读，不在计划里——记到计划外了"）。
- 凌晨 0~5 点打卡计前一日（时间基准）。
- 当日数据不完整时轻问"还剩哪些？"（≤1 轮），不追问、不打断。
- **补打卡**：任何时候可补（"昨天忘了打，阅读做了"），标注补卡日期，不计失约；补账环节顺带补量。
- **streak 清零规则**：当日无任何计划任务 → 不变；全部/部分达成 → +1；失约终态（低于最低且经对账确认）→ 清零；跨周无新计划 → 冻结，续航后续接；连续 2 天无打卡且未补账 → 暂扣待对账。
- **作息画像**：打卡时间戳累计分析，连续多日 23:00 后打卡 → 月总结输出熬夜预警与日程前移建议。
- 反作弊内规：打卡只标记"已做"，不审计时长精确性。

## 3. 完成量提取规则（判卷数据入口）

双指标判卷的数据从打卡语句进入的唯一通道：

| 打卡语句 | 提取结果 |
|---|---|
| 含数量词："背了 30 个" | 实际量 30（对比 quota_standard 判卷） |
| 程度词："报告写了一半" | 标准量 ×50% |
| 进度锚："错题整理到第 4 章" | 按 task 的换算基准折算 |
| 未提量 | 默认全量达成（quota_standard） |
| 无法量化 | 记 full/none 二值（partial 需量支撑，缺数据降级处理） |

- 提取由 checkin 子命令内置解析 + LLM 转述核对（脚本输出判卷初判，LLM 发现学生原话与解析不符时纠正重调），结果即写入 checkins.amount。
- 补账顺带补量："昨天阅读做了" → 问"大概看了多少页？"（1 轮）。

## 4. 鼓励语与每日金句

**个性化鼓励语（主通道）**：LLM 结合 checkin 输出的近期摘要（streak、本周完成率一行、昨日概况、最近偏离标记）即时生成。

- 素材贴当日完成项；风格：航海/电量/成长意象；1~2 句；不说教不堆砌。
- 示例："错题整理连着三天没断，这条航线越走越稳了。第 24 天，电量满格⚡"
- 连续打卡天数必须体现，**数据来自脚本输出，不凭印象**。

**本地语料库（兜底）**：LLM 生成受阻时回退 templates.md 语料库（20 条，随机去重，不重复上一条）。

**每日金句**：当日**首次**打卡时输出一条（后续打卡不重复）。

- 来源：从模型自身知识中检索真实可核的名人名言/大家语录（成长/坚持/探索主题优先，契合航海理念），必须附真实说话人。
- **真实性护栏（硬规则）**：宁缺毋滥——不确定是否真实存在的名言或无把握的署名，直接换一条；禁止编造人名或杜撰语录；实在没把握时跳过金句只发鼓励语。
- 去重：stats.recent_quotes 记最近 10 条，命中即换（脚本输出已过滤）。

## 5. 日终双级滚动（日级即时 + 周级兜底）

- **日终**（0~5 点分界）：当日无打卡记录的任务 → 标记"待确认"（pending_confirm），不判失约、不滚动（防冤枉）。
- 学生下次出现时**先批量补账**（1 轮内）："昨天有 2 项没打卡记录，做了吗？"
- 补账确认后立即调 `rollover`：差额 = 标准 − 实际，铺入本周内负荷 <80% 的空闲日（就近分散），受封顶约束（≤单日标准×2）。
- 滚动后明示：「明天读书任务 +5 页（来自今天的差额）⚡」
- 周级兜底见 §6 settle。

## 6. 周结算（settle）

**结算规则唯一定义处。** 生成新周计划前强制执行（航行·跨周衔接兜底由此调用）；周复盘对话前也先跑结算。

结算内容（settle 子命令一次完成）：
1. 完成度判定（判卷口径见 voyage.md §11 双指标）；
2. 差额滚动（rollover 规则）；
3. 失约累计（**对账确认后才判失约**）；
4. 完成率生成（计分口径见 §7）；
5. stats.weekly_rates 追加；
6. 周归档（weekly_plans + checkins 整周搬入 logs/archive/Wxx.json）；
7. borrow_log 核销；
8. render 刷新。

清理"待确认"残留：结算前向学生最后一次批量对账，确认后才判失约——对账未完成时 settle 输出会标 pending_confirm 清单，先补账再重跑。

## 7. 周复盘（中）

**快审模式**：学生表达"直接总结/不用聊"时跳过对话，只输出结算数据 + 三级诊断 + 司南建议；结算与日志照常。

**复盘对话**（3~5 轮，教练式）：

a. **数据回放**：本周完成率、达成/部分达成/失约清单、rollover 累计（全部来自 settle 输出，不凭记忆）；
b. **归因探询**：失约项卡在能力、时间、还是动机？（每类 ≤1 轮）；僵尸任务线索：结合 adjustment_log，把连续延后/被干预的任务作为归因探询重点素材；
c. **情绪感知**：透露疲惫/焦虑时先共情再纠偏；
d. **偏离诊断三级**：见 §8。

**完成率计分口径**（内部判卷）：按任务项计权——达成=1、部分达成=0.5、失约=0；完成率 = Σ得分 ÷ 当周任务项数。

复盘产出周总结日志（含司南建议板块），写入 logs/weekly/。

## 8. 三级偏离诊断与处置

| 级别 | 判据 | 处置 |
|---|---|---|
| 🟢 轻度 | 完成率 ≥60% 且 rollover 未封顶 | 下周一键微调（微调量/换时段） |
| 🟡 中度 | 40% ≤ 完成率 <60%，或 rollover 触封顶 | 重排下周计划（回航行阶段生成） |
| 🔴 重度 | 完成率 <40%，或连续 2 周 🟡 | 回炉对话——重审目标价值与预算，必要时降配或转换目标，走定锚修订轻流程 |

诊断结果计入 stats.weekly_rates.level，供休眠判定与仪表盘着色。

## 9. 目标休眠机制

同一目标连续 3 周 🔴 → 触发"学期战略复盘"，提供目标休眠选项：

- 数据保留、里程碑冻结、预算转其他目标，下学期可重启（status= dormant，dormant_weeks 计数）。
- 话术基调："暂停是航海中的绕行，不是弃船。"
- 休眠期间该目标不计入饥饿保护与组合体检分母；重启时按剩余周数重排里程碑。

## 10. 重度偏离心智保护

- 先处理情绪，再处理计划。
- 禁止"你落后了/你不自律"类评判性语言；用"航线偏了很正常，司南的职责就是发现并校准"框架。
- 降配不是失败：明示"调低标准是航海技术，不是放弃"。

## 11. 月度总结

- **触发**（被动补做）：每月结束后学生首次出现时，status 子命令检测上月未完成且本月已过 ≥3 天 → 一句话提示（"上个月的航线图出来了，顺便看看？"），不强推；拒绝/忽略时跳过不阻塞当前请求，下月再提示。
- **聚合**：数据来自 `aggregate` 子命令（脚本读 logs frontmatter + stats → 输出聚合表）：各周完成率→柱状图、目标时间分配→饼图、完成率趋势→折线图（图表在 dashboard.html 呈现，总结文字里引用关键数字）。
- 内容：里程碑进展回顾 + 下月航向微调建议 + 司南建议板块（行事/日程/劳娱权衡 + 熬夜预警[作息画像]）。
- 写入 logs/monthly/，调 render 刷新。

## 12. 学期/年度总结（学期归档时触发）

- 全学期完成率、里程碑达成率、目标终态（达成/延期/放弃/休眠/进行中）。
- 成长叙事：从定锚时的状态到期末的对比（呼应全面成长理念——不止学业维度）。
- 调 `archive` 子命令归档至 logs/yearly/，整目录搬入 archive/<semester>/，引导新学期重新定锚。

## 13. 日志体系（四级）与 frontmatter 规范

| 层 | 写入者 | 内容 |
|---|---|---|
| daily/ | checkin 子命令**自动追加**（LLM 零参与） | 打卡原话+时间戳+关联任务+提取量 |
| weekly/ | LLM 撰写 | 周总结（frontmatter 存机器字段，正文给学生看） |
| monthly/ | LLM 撰写 | 月总结（同规范） |
| yearly/ | LLM 撰写 | 学期总结（成长叙事+目标终态） |

**frontmatter 规范**（weekly/monthly 必须带，供 aggregate 解析）：

```yaml
---
week_id: 2026-W43
rate: 0.72
level: green
goal_hours: {eng: 5.5, dance: 3.0, math: 4.0}
---
```

monthly 用 `month_id / avg_rate / trend`；正文即学生可见叙述。目录结构见 SKILL.md 数据契约节。
